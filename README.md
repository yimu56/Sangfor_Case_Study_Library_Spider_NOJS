# 深信服案例库导出工具 (Sangfor Case Study Library Exporter)

批量抓取深信服官方知识库 [`support.sangfor.com.cn`](https://support.sangfor.com.cn)
的案例库（案例 / 解决方案），可按产品线、模块、版本、关键词、更新时间筛选，
并发翻页抓取列表与正文，还原「问题描述 / 根因 / 解决方案」的章节结构与配图，
一键导出为 **单文件 HTML / Markdown / CSV / JSON**。

**双击一个 exe 就能用** —— 不需要装浏览器插件，不需要脚本管理器（Tampermonkey /
ScriptCat 等），不需要 Python / Node 运行环境，也不需要注册或登录任何账号。

> 声明：本项目为第三方工具，与深信服科技无隶属关系，未获其官方授权或认可。

## 为什么不用用户脚本了

早期版本是一个 `.user.js` 用户脚本，必须先在浏览器里装 Tampermonkey / ScriptCat 之类的
脚本管理器才能运行。实际推广时发现这不是所有人都能接受的：

- 脚本管理器本身要装、要授权，部分企业管控的电脑还装不上；
- 换台电脑、换个浏览器就得重装一遍；
- 脚本依赖「浏览器已登录 target 站点」这一前提，状态不好解释。

这一版改成了 **单个 exe**。做法是把界面改成由 exe 内置的本地服务提供：

```
双击 exe  ──►  启动器窗口（原生窗口，负责告知地址 / 重开界面 / 退出）
                 └──►  本地服务 127.0.0.1:<随机端口>，同时提供界面与接口转发
                          └──►  系统默认浏览器打开界面
```

两个关键收益：

1. **接口转发绕开了跨域限制**。目标站点的接口不允许跨域调用（预检直接返回
   `403 Invalid CORS request`），所以浏览器里打开的网页没法直接取数；
   由本地服务代发请求就没有这个问题。
2. **不再需要登录态**。实测这些接口本身就是公开的，不带任何 Cookie 也能正常返回数据，
   脚本时代为了借用登录态而引入的那一层依赖因此整体消失。

界面放在浏览器里（而不是完全自绘原生控件）是有意为之：排版、预览、导出这些活
交给浏览器最划算，导出的文件也能走浏览器原生下载，不会被安全软件当成异常写入拦截。

## 快速开始

### 方式一：直接下载（推荐给普通用户）

1. 到 [Releases](https://github.com/yimu56/Sangfor_Case_Study_Library_Spider_NOJS/releases)
   下载最新版的 `sangfor-case-exporter.exe`。
2. 双击运行。程序会在本机启动一个本地服务，并自动用系统默认浏览器打开界面。
3. 界面里选好条件、点「开始抓取」，完成后导出即可。

exe 是**绿色单文件**，不写注册表、不需要安装，放在任意目录（含 U 盘）都能跑。

### 方式二：自己编译

见 [从源码编译](#从源码编译)。

## 使用步骤

1. **打开程序**：双击 `sangfor-case-exporter.exe`。会出现一个启动器小窗口，
   同时浏览器自动打开功能界面。
2. **选筛选条件**：
   - **产品线**：46 个可选产品线，输入关键字可快速过滤；留空表示全部产品；
   - **适用版本**：选产品线后自动加载；
   - **关键词**：匹配标题 / 模块等，留空表示不限；
   - **模块**：选产品线后加载该产品线的模块树，支持主模块 / 子模块勾选；
     勾选子模块时程序会自动把它的父主模块从筛选条件里剔除（与官网页面行为一致）。
3. **预搜索（建议先做）**：点「预搜索」会按当前条件查一次，显示命中总条数与前 8 条样例，
   确认范围没错再开抓。
4. **开始抓取**：点「▶ 开始抓取」。过程中可「暂停 / 继续 / 停止」，
   进度条和统计卡会实时显示列表页数、案例条数、正文完成数。
5. **导出**：抓取完成后选导出格式，浏览器会直接下载文件。
6. **退出**：关掉启动器小窗口即退出程序；也可以点界面右上角的「退出程序」。

> 抓取过程中请保持启动器窗口开着，关掉它程序就退出了。

## 导出格式

| 格式 | 适用场景 | 说明 |
| --- | --- | --- |
| **HTML**（推荐） | 阅读、存档、打印 PDF | 单文件、自带目录与内部分页，正文滚动到哪加载哪，几百条也不卡 |
| **Markdown** | 二次编辑、进知识库 | 含目录、章节标题、列表层级与配图 |
| **CSV** | 进 Excel 做筛选统计 | 带 UTF-8 BOM，Excel 直接打开不乱码 |
| **JSON** | 程序化处理 | 保留全部原始字段，含结构化章节数组 |

导出的字段包括：`案例ID`、`源ID`、`标题`、`产品线`、`主/子模块`、`适用版本`、
`架构版本`、`创建/更新时间`、`详情页链接`、`列表摘要`，以及正文三态
（`Markdown` / `纯文本` / `HTML`）。

仓库里带了实际的导出结果供预览：
[`样例-导出效果.html`](./样例-导出效果.html)、[`样例-导出效果.md`](./样例-导出效果.md)。

## 高级选项

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| 每页条数 | `20` | 单次请求返回条数，也决定导出 HTML 的内部分页大小 |
| 最大页数 | `0` | 本次最多抓多少页，`0` = 不限 |
| 列表并发 | `3` | 列表翻页的并发数 |
| 正文并发 | `4` | 正文详情的并发数 |
| 请求间隔（ms） | `400` | 每个请求之间的间隔，用于限速 |
| 按更新时间过滤 | 不限 | 仅保留近 `7 / 30 / 90 / 180 / 365` 天更新的案例 |
| 抓取正文详情 | 开启 | 关闭则只抓列表摘要，速度快很多 |
| 断点续爬 | 关闭 | 中断后可从中断处继续，缓存存在浏览器 `localStorage` |
| 图片内嵌为 base64 | 关闭 | 导出的文件可离线打开，但体积会明显变大 |
| HTML 分卷 | `0` | 每条文件放多少条，`0` = 单个文件 |

并发越高越快，但对目标站点压力也越大，**建议保持默认**。

## 从源码编译

需要 Go 1.21 及以上。**零第三方依赖**，`go.sum` 都不需要，
`CGO_ENABLED=0` 即可编译（所以不需要 gcc，交叉编译也没问题）。

```bash
git clone https://github.com/yimu56/Sangfor_Case_Study_Library_Spider_NOJS.git
cd Sangfor_Case_Study_Library_Spider_NOJS
CGO_ENABLED=0 go build -trimpath -ldflags="-H windowsgui -s -w" -o sangfor-case-exporter.exe .
```

Windows 上也可以直接双击 `build.bat`。

产物为单个约 7 MB 的 exe，界面资源（`web/` 目录）已经通过 `go:embed` 编进二进制里，
分发时只需要这一个文件。

## 项目结构

```
.
├── main.go              程序入口：启动服务、打开浏览器、创建启动器窗口
├── server.go            本地 HTTP 服务：静态资源 + 接口转发 + 图片转发
├── window_windows.go    原生启动器窗口（纯 syscall + GDI 自绘，零依赖）
├── web/
│   ├── index.html       功能界面结构
│   ├── app.css          界面样式
│   └── app.js           全部前端逻辑：筛选、抓取、正文解析、导出
├── go.mod
├── build.bat            一键编译
├── 样例-导出效果.html     实际导出结果样例（单文件，含目录与配图）
├── 样例-导出效果.md       实际导出结果样例
├── LICENSE
└── README.md
```

技术要点：

- **正文章节还原**：案例正文的章节标题（「问题描述」「根因」「解决方案」等）
  藏在 TinyMCE 的只读输入框 `<input value="...">` 里，简单去标签会把整个章节结构丢掉。
  `web/app.js` 里的 `SFCaseFmt` 用 DOM 解析还原层级，并处理编辑器给列表套的包装
  `<div>`、以及 `<ol>` 与其说明 `<ul>` 的归属问题。
- **列表归属修正**：官网把「有序步骤 + 其说明」渲染成 `<ol>` 与 `<ul>` 两个兄弟节点，
  语义上 `<ul>` 属于 `<ol>` 的最后一步，程序会把它收进去，Markdown 才能正确缩进。

## 常见问题

**Q：需要登录深信服账号吗？**
不需要。实测产品线、模块、版本、案例搜索、案例详情这些接口都能匿名访问。

**Q：为什么界面是用浏览器打开的，而不是原生窗口？**
界面里有大量排版、预览、导出工作，交给浏览器做效果最好，导出的文件也能走原生下载。
启动器窗口本身是原生窗口，负责提示地址与退出。

**Q：端口被占用怎么办？**
默认自动分配空闲端口，不会冲突。也可以用 `sangfor-case-exporter.exe -port 8080` 指定。

**Q：抓取到一半卡住了 / 想换条件怎么办？**
点「停止」，改完条件再点「开始抓取」。开启了断点续爬的话可以从中断处继续；
「清空断点缓存」在界面日志上方。

**Q：杀毒软件报警？**
这是 Go 编译的、无签名的单文件程序，容易被启发式规则误判。可以自行从源码编译核对。

**Q：支持 macOS / Linux 吗？**
启动器窗口目前是 Windows 专用的。核心抓取逻辑（`server.go` + `web/`）是跨平台的，
稍作改动即可移植。

## 已知限制

- **少量正文配图无法下载**：有些案例的正文里，图片在源站就只是一个编辑器占位符
  （形如 `<img src="IMG_86481717_-1843674252">`），官方接口并未给出真实地址
  （已实测多个可能的还原接口，均 404）。导出结果中这类图片会被标注成
  `[原图未公开：IMG_xxx]`，HTML 导出里显示为一条虚线提示框，不会留下破图。
  在抽样中这类占位符约占图片总数的 1/8，其余图片都在 CDN 上可正常下载。
- **深翻页上限**：搜索接口基于 Elasticsearch，最多只能翻到 10000 条。
  命中超过上限时程序会提示并自动截断，建议加产品线 / 模块 / 关键词分批抓取。
- **接口变更风险**：目标站点接口或页面结构一旦调整，程序可能失效，需要相应更新。
